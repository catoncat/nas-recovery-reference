# Btrfs 原位恢复：克隆后只改加密段

本页对应 v0.4.0。原位指最终明文留在原目录；先在临时文件上克隆改段或整份写，最后才移除密文。来源是已保存的本地实验、执行回执和进度日志，不是本仓库对现场的实时采集。

## 原理与格式

支持固定上游实现的 588 字节 EOF footer：开头 48 字节为包裹的文件 key/nonce 记录，偏移 568 是四字节会话 marker，572 起是模式/参数，580 起是原始长度。marker 必须显式提供；它不是签名，也不证明 key 正确。

- `0x24`：全部原始字节被加密，常见于小文件。
- `0x26`：只加密开头至多 1 MiB。
- `0x25`、参数 10：三段、每段约 4%，合计约 12%。其他受支持参数由固定布局解析器决定，不能一律按 12% 处理；参数 50 是五段布局。

FICLONE 共享未修改的 extents，写加密段时才发生 CoW。ChaCha8 的 counter 在各段间连续，且受调用分块规则约束；不能直接按文件偏移推导。布局和 unwrap 复用固定上游；ChaCha8 默认尝试经启动自检的 C 后端，缺失时回退既有 Python/NumPy 实现，保持相同分块与 counter 语义。

整份复制还要搬运没有加密的字节。原位方式减少这些读写，但仍需要加密段、元数据和在途克隆的空间；快照、其他引用及 CoW 分配均可能阻止旧块回收，不能把“净增约零”当容量保证。

## 适用条件

- 已取得、备份并在本会话支持格式上验证过有效材料；已有验证直接复用。
- Linux/Btrfs 上 FICLONE 与 libc `syncfs` 可用。根目录和状态目录在同一文件系统，临时文件与源文件同目录。只接受独立普通文件，拒绝符号链接、硬链接源和跨到其他文件系统的文件。
- 受灾 NAS 保持隔离；本任务独占所选目录，不与旧复制清单、业务写入或另一个恢复控制器竞争。每个文件系统只运行一套恢复长任务；状态锁只能阻止同一状态目录重复启动，不能发现不同状态目录的重复任务。
- 保留空闲空间预算，并把 footer 归档和 key 备份到独立安全位置。日志含真实文件名、路径和 footer，只能放私有位置。
- 代码保留 uid/gid、mode、atime/mtime；**不复制逐文件 xattr/ACL、稀疏布局或所有系统属性**。需要这些属性时先完成适配；同目录 ACL 继承不能替代逐文件 ACL。根目录不能重叠，状态不能放进来源树；信任并独占所有父目录，不防御并发恶意换目录。

选择克隆的文件若 FICLONE 不可用，工具记错误并保留密文；不会把克隆错误当成低空间切换。改走 [复制到新位置](CODE.md)，交付仍须包含未加密原件。

## 每批提交的准确顺序

扫描 → 有界路径队列 → 常驻 worker 按空间策略准备并解密 → 有界结果队列 → 独立提交线程。约 256 文件或 10 秒一批；worker 可在提交线程工作时继续准备。

1. 在同目录排他创建临时文件，按策略克隆改段或从只读源整份写入（明文段直接复制、密文段解密），做文件头检查，截掉 footer，恢复基本元数据。源文件此时保持不动。
2. 把本批 footer、源身份、目标身份和路径追加到 `footer-archive.jsonl`。
3. 对本文件系统执行 `syncfs`。本批临时明文和归档，以及上一批 link/unlink 一起持久化。同步失败则不进入本批删除。
4. 用不覆盖的 `link` 安装原名，删除临时链接；再次核对源身份后删除密文。已有原名且无归档时记冲突；有归档时重新生成明文逐字节比较后才能接续。
5. 写上一批的 `completed.jsonl`；本批仍计入 `installed_pending_files/bytes`，不计正式完成。下一批的屏障后才计完成。
6. 根边界、STOP 或 EOF 没有下一批时，额外一次 `syncfs` 排空，补写最后一批完成记录。

归档与磁盘上的文件身份是续跑依据，SQLite 只是可重建索引。每根的完成数从 completed 日志重放到内存，再随完成事件累计，根边界只读内存，避免对百万行 SQLite 逐根全表汇总；普通冷启动仍需重放日志，不承诺恒定启动耗时。完成日志可能在意外中断时落后于已安装文件，不能为了对齐计数而删源或删状态。`root-done` 只表示本轮扫描结束，可能仍有 skipped/conflicts/errors。

## 参数与运行

依赖先按 [CODE.md](CODE.md) 在干净机器准备；`RECOVERY_CRYPTO_ROOT` 指向另行取得的固定上游，每次导入前验证摘要。不要在受灾设备升级依赖。

以下都是合成路径占位；替换为本事件的明确范围。`REVIEWED_8_HEX_MARKER` 也必须替换。`key-stdin.py` 读取私有的 48 字节文件并直接向子进程 stdin 发送 `KEY48:` 协议，不打印到终端，不把 key 放 argv/环境变量。

```sh
umask 077
python3 -B scripts/key-stdin.py --key-file /analysis/private/session-key.bin -- \
  python3 -B scripts/inplace-recover.py \
    --marker REVIEWED_8_HEX_MARKER --suffix .L0CK3D \
    --state /data/private-recovery-state --reserve-gb 200 --threads 8 \
    --clone-above-gb 800 --safety-gb 16 --newest-year 2026 \
    --exclude-name private-tools --execute \
    /data/selected-files /data/next-files
```

根目录按参数顺序处理，内部用 4 线程 scandir 流式扫描，不保证词典顺序。可用 `--newest-year` 指定最高年份：该年份发现即派发，旧年份路径落入磁盘队列，扫描后按年份倒序派发；未识别年份最后处理。根顺序仍高于年份顺序，先传入急需的互不重叠根，不要同时传父根和子根。

默认精确排除 `@eaDir`、`@sharesnap`、`#snapshot`、`@tmp`、`@__thumb`、`@SynoResource`、`@SynoEAStream`。`--exclude-name` 增补精确的文件/目录 basename，不匹配前缀；工具、状态、测试目录须逐一加入，状态目录必须在来源树外。`@user`、`#files`、`#backup`、`#recycle` 和隐藏目录都会进入恢复。**v0.3.0 的 `--exclude-prefix @ --exclude-prefix '#recycle'` 示例已撤回**，它会漏掉用户数据及回收站；旧参数现在拒绝使用。省略 `--execute` 会拒绝启动。

## 自适应写和空间预算

**更正：原位克隆净增空间约等于零是错误判断。** Btrfs bookend extent 在局部仍被引用时整段旧 extent 不能释放；局部改写会让旧字节残留，累计增占可接近改写量，已有局部加密负载约为完整文件大小的 9–12%（局部样本）。原理见 [Btrfs 数据 extent 引用说明](https://github.com/btrfs/btrfs-dev-docs/blob/master/data-extent-reference-counts.md)。这不是内存泄漏，也不保证每个文件都按固定比例增占；快照和其他引用会加重占用。

空间取 `btrfs filesystem usage -b` 的 Free minimum，并由独立 data chunk 空闲加 device unallocated 封顶，不把 metadata 空闲当作数据容量。`statvfs` 只作旁注。每 15 秒采样，失败时可用预算置零；预算额外扣除在途文件、采样后分配和 `--safety-gb`。`--reserve-gb` 是不可突破的保留量，正式数据不要设为零。

- 文件不大于 `--small-file-bytes`（默认 1 MiB），或完整大小不大于改写字节的 4 倍，始终整份写；全加密文件也走整份写。
- 其余文件的保守可用预算高于 `--clone-above-gb`（默认 800 十进制 GB）时克隆改段，低于或等于阈值时整份写。
- 整份写要先容纳一整份临时明文，不能靠以后删源的空间启动。空间不足则 `paused-low-space`，不删源；释放、报错或取消的分配仍保守计费到下一次内核采样。
- 上述默认值是参考配置，不是适合所有卷的容量保证。根据最大文件、并发、快照和其他写入调预留；估计克隆残留与源逻辑删量分别报告。

公开版在小文件/全加密文件上比生产源工具更保守地使用整份写；生产源工具保留了全加密模式克隆的特例。没有导出现场的快速交接、跨卷调度和硬编码排除目录。

## 停止、续跑和撤回

在私有状态目录创建 `STOP_REQUESTED`，停止扫描并排空在途文件/最后一批。确认 `status.json` 为 stopped、原控制器已退出且锁可取后，保留全部状态，用相同版本、根列表、marker、suffix、排除参数续跑；仅在明确继续时移除 STOP。不要为了测试、测速或等待而停生产控制器；测试在独立目录并行做，仅切换已验证代码时短暂停稳并立即接续。线程可通过状态目录 `THREADS` 文件设为 1–24，下批热更新。不同负载不能照搬本次最快线程数。

本版本的状态配置包含精确排除及空间/年份参数，直接复用 v0.3.0 配置会拒绝；先独立评估迁移，不改配置文件绕过检查。相同 v0.4.0 版本和配置的续跑会重建 SQLite、修剪日志最后一条被截断的 JSON、清除命名匹配的遗留临时文件。中间日志损坏直接报错。源已删除、完成日志缺失时，复核已归档目标的 dev/inode/size 后补记；源仍在且原名已安装时重新生成并比较。此身份检查不证明中断后有人修改过的内容仍是原文，所以续跑期间仍须独占目录。

撤回使用同一状态锁，恢复控制器必须退出。只选择实际要撤回的归档源路径：

```sh
python3 -B scripts/key-stdin.py --key-file /analysis/private/session-key.bin -- \
  python3 -B scripts/inplace-revert.py \
    /data/private-recovery-state/footer-archive.jsonl \
    --marker REVIEWED_8_HEX_MARKER \
    --source /data/selected-files/example.jpg.L0CK3D --execute
```

`--source` 可重复；需要全量时显式 `--all`。撤回克隆当前明文，按归档 footer 再异或，加回 footer；先把重建密文链接持久化，再删明文。原密文名已存在时保留两边，不覆盖。撤回前必须保证明文从恢复后未被修改；归档只有 footer 和身份，没有全文件历史内容，不能撤回用户后续编辑，也不能替代备份。撤回中断可能留下两份或临时文件，保留核对。撤回后再恢复使用**新状态目录**，因为重建密文 inode 已变；保留旧归档。

## C 后端、性能和卡顿

源码及原生/交叉编译命令见 [NATIVE-CIPHER.md](NATIVE-CIPHER.md)。不分发二进制；本地编译物不能直接搬到另一架构。加载库前核对可信构建摘要和权限，启动会以公开固定输入比对 Python/NumPy，缺库或 ABI 不匹配会回退，并在 status 记录原因。自检只能筛查兼容错误，不能为不可信共享库提供沙箱。

源工具历史现场：2026-11-01 原先解密调用约百毫秒，C 后端后约 2–5 ms，代表窗口见 [脱敏性能记录](evidence/v0.4.0-field-summary.json)；指令汇总另报告两卷合计峰值约 1 GB/s（未附可复算窗口的历史约数）；已有可复核 5 分钟窗口为 830.02 MB/s，均为逻辑完成速率，最终更多等待磁盘，不能把逻辑文件字节当物理写入或硬件保证。用 `nice -n 10 ionice -c 2 -n 7` 启动可降低对管理 IO 的影响；先确认平台支持，降低优先级并非增加磁盘能力。

2026-11-02 的旧根汇总耗时 1382.864 秒，改成内存累计后生产汇总写回约 0.189–0.498 秒（部分根整个收尾约 1 秒）。另一次 RAID5 成员盘约 90–95% 忙，clone 从约 100 ms 拉长到约 5 秒；大批 unlink 会加重元数据提交压力，不能仅凭相关性断言删除是唯一原因。先看成员盘忙碌度、Btrfs delayed refs 和事务等待，再调线程、队列、批次及删除节奏。

跨卷腾空间、收尾和零复制交付见 [恢复后操作](RECOVERY-FINISHING.md)；保留数据重装见 [重建说明](REBUILD.md)。这些文档不是本导出代码已经部署或全盘完成的证明。
