# 救援手册：按证据推进

这是客户技术人员用于制定本事件执行计划的参考。每阶段明确来源、输出、负责人和放行条件，不将某次现场的 PID、设备号或 key 套到其他事件。

## 1. 接管现场，保留选择

现场管理员负责保持受灾设备供电，切断其公网和业务网络传播路径，记录接线、设备及时间。暂缓升级、重装、重启、格式化、磁盘修复和会自动清理历史版本的维护作业。先记录事实，再选择具体措施；“还没重启”只能说明仍值得评估易失证据，不能保证密钥还在。

远程支持应经过干净管理机和受控入口。管理机同时连接互联网和 NAS 时，要核对路由、网桥、转发及 IPv6 暴露。双网卡本身不证明隔离。受灾系统提供的命令输出是证据之一，不能单靠它证明系统可信。

本阶段交付：时间线、网络连接图、存储池与磁盘身份、管理员联系人、已允许的读取/状态变更范围。随后才可决定具体进程调查与证据保存方法。

## 2. 确认进程身份，保护易失证据

事件响应技术人员记录候选 PID、启动时刻/start_ticks、可执行文件摘要、线程状态和文件活动。不能只凭名称、CPU 高、`(deleted)` 或单个主线程状态判断。PID 可能被复用，操作前必须重新核对身份。

确认确为加密进程且完成具体操作评估后，按事件负责人批准的方案冻结指定实例，再逐线程验证。T 表示停止/跟踪状态；D 不是已停稳，已有 I/O 可能继续。不要按名称群发信号，也不要因为冻结成功就继续杀进程或重启。

保存内存时，要区分 process mappings、物理 RAM、QEMU 映射、LiME、ELF 与 swap。格式不相容时不能拼接或改扩展名冒充。记录 holes、排除范围、部分采集、进程身份及输出摘要。独立目标要核对底层设备/存储池和空闲空间；不同路径、不同设备号都不能单独证明物理独立。`/tmp` 未必在 RAM。

本包不实现内存采集。参见固定上游与 [Linux proc 官方文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html)，采集能力与权限以实际系统为准。

## 3. 先找直接恢复路线

存储管理员清点可信离线备份、历史版本和只读快照，记录来源时间、保留策略及抽样内容。快照目录为空、没有可疑后缀或文件能预览，都不足以证明副本可用。Btrfs 的 CoW/旧 extent 路线受布局和块是否保留影响，参见 [Btrfs 官方管理说明](https://btrfs.readthedocs.io/en/latest/Administration.html)。

| 已有条件 | 优先评估路线 | 必须留下的结果 |
|---|---|---|
| 有可信历史副本 | 从副本恢复到全新目标 | 来源、时间、内容校验与缺项 |
| 有匹配的会话材料和支持格式 | 小样本验证后，精确清单批量恢复 | key 适用分组、模式、异常及验证等级 |
| 有内存证据但无已验证 key | 离线分析匹配样本/profile | 证据格式、覆盖区段、候选与阴性范围 |
| 无有效 key，Btrfs 旧块可能保留 | 单文件专项重建与校验 | exact/inference/partial/lost/unsupported 分级 |
| 格式或存储布局未知 | 保全证据，另行适配 | unknown/unsupported，不猜成功 |

## 4. 小范围验证：先证明可以恢复什么

恢复工程师在独立密文副本上检查 footer、模式、长度和会话分组，覆盖观察到的不同模式与大小。不要以 marker 相同推出同一 key，也不要以 nonce 重复检验当作完整 key/IV 认证。

优先用可信历史原件的完整 SHA-256 比较。没有历史原件时，图片完整解码、ZIP 全成员 CRC、视频完整音视频解码、PDF 全页解析与渲染、数据库一致性等可以提供结构证据。验证工具在隔离环境处理副本，不运行恢复出的程序或业务服务。

| 结果 | 含义 |
|---|---|
| 原件完整 hash 匹配 | 对应可信原件字节一致 |
| 结构检查通过 | 覆盖的结构检查通过，不能证明与历史原件逐字节一致 |
| 恢复输出读回 hash 匹配 | 磁盘逻辑读回与本次生成的输出一致，不认证 key/IV 或历史内容 |
| 仅 key record/nonce 检查通过 | 候选线索，未证明恢复成功 |
| failed/partial/unsupported/unknown | 保留原因与原始材料，不能改成成功 |

## 5. 明确业务优先级和容量，再启动批次

资料负责人指定最急的选定目录，技术人员只清点该范围，列明排除项、读取错误、目标命名冲突和预计输出大小。已有完整清单应复用；后台范围调查为正式恢复让出 I/O。清点完成与恢复完成分开记录。

本包当前格式的输出长度按密文长度减 588 字节估算；这不代表 footer 已验证。容量还要考虑文件系统元数据、空闲保留和其他作业。代码固定保留 50 GB 操作空间和 10 GB 元数据预算，因此不适合直接用于小于此预算的目标盘。

启动前在执行机核对目标 UUID、设备/USB 身份、挂载、可写性和实际剩余空间，确认源/目标/控制目录不重叠。盘符或挂载路径复用不等于还是原设备。原机不同容量池仍处在同一受灾系统故障域。

## 6. 批量恢复、暂停和接续

按 [代码手册](CODE.md) 生成并审阅精确清单。默认检查不写业务输出；显式执行时才创建新文件。密钥从受控 stdin 输入，不进入 argv、环境变量、命令历史或日志。清单和完成日志有真实路径，始终作为本客户的私有材料。

每份完成要有持久化记录，统计只计完整完成文件。暂停采用文件边界停发、在途文件排空、登记成功输出的顺序。接续使用同一清单、设备身份和状态目录；不能因为观察器超时再启动一份任务，也不能重跑历史启动封装。

没有完成记录的现存文件属于待核对输出：有本任务意图时重新证明，无意图则冲突。错误或部分输出不覆盖。详细故障分支见 [架构说明](ARCHITECTURE.md)。

## 7. 尽早交付选定目录

交付工程师按选定目录提供只读访问，不必等待全盘恢复。技术放行至少包含：预定全部文件都有有效完成记录、实际目录无额外文件/链接/跨挂载、输出未变化、抽样内容验收和权限核对。

`publication-eligibility.py` 只覆盖其中的目录与日志资格观察，返回 `published=false`。它不会设置账号、HTTPS、共享、权限或防止检查之后的修改。实际服务需干净主机、访问隔离、只读权限、外部入口核对和发布后读回；不重新对外开放受感染 NAS。

恢复、业务验收与环境清理分别结案。重建干净系统、修补入口、轮换凭据、验证备份以及决定原证据保留期，都有各自负责人；解密成功不证明入侵清除或无数据外传。
