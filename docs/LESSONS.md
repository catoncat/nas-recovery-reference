# 脱敏复盘：可以带走的方法

整理日期：2026-11-01（Asia/Taipei）。本页来源于本次已保存的操作记录、代码审查和合成测试；不重新扫描现场，也不提供客户名、文件路径、网络地址或 key。

## 已有现场证据，怎样解释

本次曾保全仍存活的加密进程相关证据，取得本次适用的会话材料，并在新位置恢复若干业务目录。已有样本通过图片完整解码、归档 CRC、PDF 解析渲染、音视频解码等结构检查。没有可信历史原件完整 hash 的样本仍只标结构验证通过，不能宣称与历史原件逐字节一致，也不由抽样推全量。

截至本次整理，整体救援未结束，业务恢复处于暂停阶段。部分范围统计完整、部分仅为下限；不是全 NAS 已恢复。本次的 key 和默认配置对另一客户没有可推定的适用性。

## 最有价值的操作经验

1. **先保全会随重启消失的证据。** 升级和重装有其必要阶段，但启动顺序要给易失证据留出机会。未重启也不保证有可用 key。
2. **状态写进可复用入口。** 当前任务、暂停原因、真实设备身份、日志位置和接续条件必须交接。历史命令不等于再次执行的指令，观察器退出不等于业务进程退出。
3. **让恢复优先于求全调查。** 已有清单复用，急需目录先恢复；范围扫描不抢同一磁盘资源。某个目录结构统计完整并不证明其内容恢复完成。
4. **用文件集合交付。** 选定目录可先提供只读访问；只计完整文件，目录缺项就保留待处理，避免强行凑“完成”。
5. **核对设备身份而非路径名。** 同一个 USB 挂载路径先后对应不同盘，文件系统兼容性、容量和设备身份都要重新核对。独立容量池不是独立受灾主机。
6. **预览错误要追到文件。** 本次某图片在原平台预览失败，但读回摘要与恢复日志一致，完整解码也成功。它只证明该文件通过所做检查，不能反推所有预览失败都无害或全部文件无损。

## 性能经验：保留口径，才可比较

历史业务采样（2026-11-01）按完整文件记账，正常运行窗口的整体吞吐约 32 MB/s；另一个短时合成管线约 83 MB/s。两者的输入分布、文件布局、调度、日志持久化和缓存条件不同，不是同一基准，更不是对其他客户的速度承诺。MB/s 使用十进制字节口径。

源阵列等待、目录访问、日志同步、算法、hash、写入和读回均可能占时间。完整逻辑读回可能命中页缓存，不能据此声称物理 SSD 被完整读取第二遍。线程累计阶段时间也不能直接相加当作墙钟时间。

本次代码审查看到了可削减的工作：正常新输出的重复同步、逐文件主线程日志屏障、对既有目录反复 mkdir、全历史完成计数遍历。v2/v3 在独立文件中优化了这些路径，保留完整读回和持久化顺序。合成测试显示部分调用数减少；尚无原现场部署和真实长期吞吐证据。减少 fsync 调用数量不等于同倍数提速。

## 格式与密码学易错点

固定实现处理 588 字节 footer 的已知布局。文件 key 记录位于 footer 开头 48 字节，不是整个文件最后 48 字节。ChaCha8 不等于标准 ChaCha20；分段、调用边界和 counter 消耗不能按文件偏移凭直觉重写。

CBC 的 IV 错误可能只影响首个解出的明文块，因此 nonce 重复仍可能通过。marker、nonce 或某个结构签名只提供部分证据。本包不附通用 key、不重新实现密码学、不在新客户设备盲套样本地址。

## 本次没有证明的事

- 所有目录、所有文件或所有会话都已恢复。
- 原 NAS 已清洁，或不存在数据外传。
- v2/v3 真实环境性能优于基线，或某个并发数普遍最优。
- Btrfs 块重建、任意物理 RAM 获取、Windows/macOS 网络源客户端适配可直接使用。
- 发布资格检查通过后，网站、账号、用户权限和外网 HTTPS 已上线。

这些空白保留为适配/验收项目，客户技术人员可以据此明确下一步要补什么证据。
