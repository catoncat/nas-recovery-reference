# 代码结构与故障边界

代码有意保留基线和候选三个独立文件，以便审查差异。`PROVENANCE.json` 记录导出前后摘要及脱敏变换；原现场脚本没有被本包替换。

| 文件 | 职责 |
|---|---|
| recover.py | 单一明确来源目录的通用 plan/run 入口，显式 marker 与范围 |
| october-export-manifest.py | 元数据清单、预计输出量、可移植命名/冲突/容量检查 |
| october-export-runner.py | 精确清单、设备绑定、意图/完成日志、8 worker 和暂停接续基线 |
| october-export-runner-v2.py | 合批日志、去重复同步、分段计时、既有目录先 open 的离线候选 |
| october-export-runner-v3.py | 有界提前登记、目录准备 LRU、增量统计、可关闭的目录调度限制候选 |
| attested-recovery.py | 源正文 hash 与本次输出绑定、流式解密、输出完整读回及孤儿证明 |
| recovery-paths.py | 仅抽取路径/身份、只读和私有目录辅助函数；不含删源 Runner |
| publication-eligibility.py | 已完成目录与精确清单资格核对；不发布共享 |
| check-dependencies.py | 导入前核对客户另行取得的固定上游脚本摘要 |

## 正常新文件的顺序

1. 核对清单摘要、来源身份、设备身份和实际空间，检查不存在冲突。
2. 将明确的 creation intent 写日志并 fsync，之后才可提交创建。
3. 以只读方式打开源、排他创建新输出，边读/解密/写边计算摘要。明文文件走复制分支。
4. 同步新输出与目录；完整逻辑读回并核对输出 hash、长度和身份。
5. 将源/目标对应关系及验证证明写 complete 记录并 fsync，之后才计数。

v2/v3 可将一组日志同步合批，但必须保持“意图先持久化再创建、完成先持久化再计数”。完整逻辑读回保留。它可能命中 OS 页缓存；fsync 的断电语义依赖实际设备、驱动与文件系统正确实现。本次测试包含进程退出，不是拔盘/断电认证。

## 中断后如何处理

| 中断位置或异常 | 处理 |
|---|---|
| 已有 complete 且身份/证明仍匹配 | 复用原读回证据，不重新恢复；不据此抵御恶意管理员伪造元数据 |
| 有本任务 intent，文件完整但无 complete | 加密文件实际重解密比较，明文文件重算源摘要，完整读回后才采用 |
| 有 intent，现存输出部分或错误 | 保留输出与源，拒绝覆盖，等待显式核对 |
| 现存输出没有本任务 intent | 冲突，拒绝覆盖 |
| 自己的有效日志头之后末尾残缺 JSONL | 仅截去未完整追加的末尾；对应输出仍需孤儿证明 |
| 容量、源身份、设备或路径校验失败 | 不再将该文件计成功；停止后检查在途文件与已持久化记录 |
| 正常暂停标记 | 停止提交，排空在途任务并登记成功输出，保留暂停标记 |

生产者在异常时可能删除**自己刚创建、尚未完成的明文输出**；不是删除原密文，也不会清理原有孤儿输出。状态快照通过替换本任务自己的临时状态文件更新。包内不存在密文删源事务、自动磁盘格式化、进程冻结/杀进程或自动重启入口。

## 证明的含义

`source_attestation` 把本次读到的密文摘要、源身份、输出摘要与路径对应起来，利于审查和中断接续。它不是数字签名，不证明系统未被入侵，不认证 key/IV，不替代历史原件或结构/业务验证。

所有路径、日志和程序目录需要可信独占管理；攻击者若仍有 root 权限，可能篡改代码、日志、元数据或检查之后的文件。实际部署必须按事件隔离条件评估，代码检查不能替代该前提。

## 性能比较规则

同一来源文件组、输出介质、并发和缓存条件下比较，记录完整文件完成量/墙钟时间、读写设备计数与分段日志。线程累计耗时不等于墙钟，各层设备字节不能相加当作有效资料速度。候选的系统调用减少只证明少做了对应工作，没有真实吞吐倍数含义。
