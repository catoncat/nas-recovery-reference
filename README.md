本包把一次真实 NAS 救援中的处置顺序、恢复调度代码和失败处理方法整理为可复用材料。适合客户 IT、存储管理员和事件响应技术人员先在隔离测试环境阅读、演练，再按各自事件证据适配。

**核心前提：这里没有通用解密密钥。** 只有匹配的文件格式、有效的本次会话材料和经过验证的输出条件同时成立，解密路线才可能成立。未知变种、无有效密钥、原数据已经被覆盖等情况，需要其他恢复路线。

## 包含什么

- 不删源的单向恢复调度器：基线、v2、v3 三个独立文件；v2/v3 在该资料快照时属于尚未部署的优化候选。
- 单一明确目录的通用入口 `scripts/recover.py`，强制指定来源、目标、清单摘要和 marker。
- 源/输出身份、容量与设备校验，完整输出读回，持久化完成日志和中断接续。
- 目录发布资格检查库与合成测试。该库不会上线共享或配置账号。
- `DEPENDENCIES.json`、`PROVENANCE.json` 和 `SHA256SUMS`，用于核对依赖、代码导出关系和包内文件。

不包含现场客户文件、真实路径清单、IP/账号/SSH 配置、内存转储、会话密钥、密钥备份、恶意程序或第三方源码。取证与密钥获取作为手册步骤和上游引用提供，没有自动冻结/杀进程/采集内存入口。密文删源事务没有收入本包；程序失败时可能清理自己刚创建的未完成明文，详见代码边界。

## 当前证据强度

本次现场已有若干目录恢复成果，整体救援仍未结束。本包不是全 NAS 恢复完成证明。原现场在 2026-11-01 已采集的状态显示业务恢复暂停；本包整理没有连接、重启或改变现场任务。

包内自测全部使用临时合成数据，具体环境和结果见 [验证记录](VALIDATION.json)。通过这些测试可以检查已覆盖的日志、路径和故障分支；其他客户的设备、格式、密钥与真实业务内容仍需独立验收。

## 最快开始

先阅读 [第三方说明](THIRD-PARTY-NOTICES.md) 和 [依赖准备](docs/CODE.md)，在干净分析机自行取得匹配的上游依赖。然后执行：

```sh
python3 scripts/check-dependencies.py
python3 scripts/selftest.py
python3 scripts/recover.py --help
```

不要在受灾 NAS 上为运行本包升级 Python 或安装依赖。Linux USB 设备探测是当前代码的实际适配范围；Windows、macOS 网络挂载客户端和任意 SMB 源尚未实现。
